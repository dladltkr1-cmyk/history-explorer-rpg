# 고대 국가 생활 성장 설계 — v49

현재 구현값이다. 역사 본편·다음 시대가 붙어도 `ancient.home`의 소유 기록을 이어받는다. 평판은 역사적 사회 신분이 아니며 엽전은 게임용 가상 화폐다.

## 평판·꾸미기

평판 최대100. 첫 수확1, 집 확장2, 부탁2~4, 운송4~5. 명칭: 0~9 새로 온 사람 /10~29 마을에 익숙한 사람 /30~54 믿음받는 사람 /55~79 이름난 사람 /80~100 마을의 신뢰를 얻은 사람.

기존12종에 6종 추가: 누비 침구75(평판10), 곡식 진열대58, 목재 선반68, 무늬 짠 발64(벽), 마당 그늘막110(평판30), 식사 자리82. 침구를 실제 집 안에 배치하면 집 휴식 최소회복 목표가 최대HP의30%→40%. 다른 장식은 전투 능력치를 바꾸지 않는다. 슬롯/소유수량/회수·재배치 계약은 기존 동일.

새 에셋13개는 `dist/assets/life2/*.svg`; 생성기 `scripts/create-life2-assets.mjs`. 기존 거처 벡터 소품의 선/흙/목재 색을 맞추며 수레 바퀴·짐판·손잡이·짐, 화로2솥, 낫 곡선 철날, 게시판3쪽지 등 개별 실루엣을 만든다.

## 저장·확장 계약

`saveVersion:3`, 개인 코드·서버 전송 계약은 그대로. `lifeRevision:2` 및 `ancient.home.commerce` 추가. commerce에는 revision, orders[{id,key}], nextId, completed, history(최근30), focus, tools, legacyBulkHarvest, cart{owned,commissioned,active:{id,key,country}|null,nextId,completed}를 저장한다. 보상/요구량은 저장된 숫자를 신뢰하지 않고 정의에서 계산한다. 완료 카드 ID가 즉시 교체되므로 이중 클릭/같은 저장 복원 후 이전 ID 재납품이 실패한다. v48.1 lifeRevision1은 집/씨앗/작물/배치/재산을 보존하고 기존 모두 수확 편의를 legacyBulkHarvest로 유지한다. 시간 역행 시 성장은 음수가 되지 않고 수확은 칸을 비워 중복 지급을 막는다. 기기 시계 자체의 고의 변경 검증에는 향후 서버 기준 시간이 필요하다.

후속 스토리는 `meetsLifeRequirements`와 독립 해금 정의를 사용한다. 새 왕/4·5·6세기 본편/다음 시대 진입은 아직 만들지 않았다. 향후 시대 진입에서도 `ancient.home`을 초기화하지 말 것.

## QA와 경제 모델

기존 공유 상호작용 시험→내 거처의 생활2차 준비 버튼으로 신규0/기존4, 부족/충분, 평판0·8·22·45·100, 부탁생성/물품부족/완료, 도구전후, 화로전후, 수레제작/운송/도착/취소/복원을 준비한다. 원본 학생과 시험 기록을 분리한다.

`analyze-life-economy.mjs`는 관리자 재화 없이 지급 씨앗/목재로 출발하고 실제 생산·가격·납품·구매·성장 함수를 사용한다. 시계는 명시적으로 가속한 모델이다. 씨앗 주머니 먼저 구매한 뒤 농사만 반복: 주머니16분, 2단계40.5분, 3단계75.5분, 4단계122분. 기존 낚시/사냥 추가 순수입3엽전/분을 가정한 혼합 모델: 주머니12.75분, 2단계32분, 3단계60.25분, 4단계99.75분. 혼합 추가 수입은 가정이며 실제 전투/낚시 평균 측정값이 아니다. 이동·독서·선택 시간, 낫/화로/수레/꾸미기 투자에 따라 더 걸린다. 장기 추적을 위한 기준이며 실제 학생 태블릿 장시간 측정 결과로 표현하지 않는다.
